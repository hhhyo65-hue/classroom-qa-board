  IMPORTANT BUG FOUND: with "Automatically expose new tables" OFF, Supabase does NOT grant
  select/insert/update/delete on new tables to service_role either (not just anon/authenticated).
  This caused createQuestion() to silently fail with a generic "저장에 실패했습니다" error.
  Fix: explicitly run
    grant select, insert, update, delete on questions to service_role;
  in the SQL editor after creating any table when this project setting is off. service_role still
  bypasses RLS row-checks, but it needs the same table-level GRANTs as any other role via PostgREST.

  legacy service_role JWT) in .env.local, no NEXT_PUBLIC_ prefix.

Browser automation notes (for future rounds of this task or similar):
- Ctrl+A/Ctrl+Home/Ctrl+Shift+End often act at the OS/browser-chrome level (select whole page) rather
  than inside a focused CodeMirror/Monaco editor or textarea in this environment. Prefer triple_click
  to select a line, or read_page refs + form_input for form fields, over keyboard select-all.
  For Monaco-based editors (Supabase SQL editor), the most reliable way to set content is
  `window.monaco.editor.getModels()[0].setValue(...)` via the JS tool, not simulated typing.
- Screenshot pixel coordinates and read_page ref click coordinates are not always the same scale
  (screenshot was 800px wide, viewport reported 961px) — prefer ref-based clicks/form_input over
  raw coordinates when a read_page ref is available.
